# 输入行为驱动的留言页空闲返回优化设计

- 日期：2026-05-10
- 项目：children-show
- 范围：`public/index.html`

## 目标

把留言页的 2 分钟自动返回机制，从“进入页面后开始计时”改为“最后一次有效输入行为后开始计时”，避免孩子正在思考或持续输入时被强制返回。

## 不变约束

1. 保留“先留言，才能看到大家的悄悄话”机制。
2. 保留发送成功后展示留言并启动 60 秒返回首页倒计时的机制。
3. 不改角色切换、返回按钮、审核流程、留言加载逻辑。
4. 只做最小必要改动，不拆分现有页面结构。

## 新交互规则

### 进入留言页

- 进入留言页后，仍然存在 2 分钟自动返回机制。
- 但这 2 分钟不再简单按“进入页面的时间”计算，而是按“最近一次有效输入行为”计算。

### 有效输入行为

以下行为算作有效输入行为，并且每次发生时都重置 2 分钟计时：

- 键盘输入字符
- 删除字符
- 粘贴内容
- 剪切导致内容变化
- 输入法上屏导致内容变化

统一以输入框的 `input` 事件作为判断依据。

### 不算有效输入行为

以下行为不重置 2 分钟计时：

- 只是点击输入框
- 只是让输入框获得焦点
- 只是唤起键盘但没有实际输入
- 滑动页面
- 点击返回按钮
- 点击切换角色按钮
- 其他与输入框内容无关的页面交互

### 自动返回触发条件

- 如果留言页中连续 2 分钟没有新的有效输入行为，则自动返回角色选择页。
- 如果孩子持续输入，则因为每次输入都会刷新计时，所以不会触发自动返回。
- 如果孩子输入了几个字后离开，只要连续 2 分钟没有继续输入，也会自动返回。

## 代码设计

### 保留现有结构

继续保留：

- `IDLE_TIMEOUT = 120`
- `showRolesView()` 作为统一返回入口
- `startIdleTimer()` / `clearIdleTimer()` 这组空闲计时函数名

这样可以把改动控制在现有空闲逻辑附近，而不影响其他流程。

### 修改点

#### 1. 留言页初始化行为

当前进入留言页时会直接启动一次固定的 2 分钟空闲定时器。

调整后：

- 进入留言页时仍启动一个 2 分钟定时器，作为初始等待窗口。
- 如果孩子开始输入，则每次 `input` 事件都重置该定时器。

这意味着：

- 进入页面后一直不输入，2 分钟后返回。
- 开始输入后，只看“最后一次输入距离现在多久”。

#### 2. 输入框事件绑定

给 `#msg-input` 增加 `input` 事件监听。

监听器行为：

- 每次收到 `input` 事件时，调用重置空闲计时逻辑。
- 不关心输入后的内容长度，只关心“内容是否发生变化”。

不额外绑定 `focus`、`click`、`keydown`、`touchstart` 作为空闲刷新来源，避免误判“仍在输入”。

#### 3. 空闲计时函数语义调整

`startIdleTimer()` 的职责调整为：

- 清掉旧定时器
- 重新创建一个 2 分钟后触发的返回定时器

也就是说，它实际上承担“启动或重置空闲计时”的职责。

`clearIdleTimer()` 继续负责彻底清掉空闲定时器。

#### 4. 发送成功后的关系处理

发送成功后：

- 现有逻辑会隐藏“先留言提示”、显示留言列表、加载历史留言、并启动 60 秒展示倒计时。
- 本次改动不改变这部分行为。
- 一旦发送成功进入展示阶段，页面主导倒计时仍然是现有 60 秒返回机制。

因此本次优化只作用于“留言前的输入阶段”，不扩展到“留言后展示阶段”。

## 数据流与状态边界

### 输入前阶段

状态特征：

- `preSendHint` 可见
- `messageList` 隐藏
- 空闲计时以 2 分钟无有效输入为准

### 输入中阶段

状态特征：

- 仍属于留言前阶段
- 每次 `input` 事件重置 2 分钟空闲计时

### 发送后阶段

状态特征：

- `preSendHint` 隐藏
- `messageList` 显示
- 空闲返回主逻辑切换为现有 60 秒展示倒计时
- 留言前的 2 分钟空闲计时不再作为主导规则

## 错误处理

本次不新增额外错误处理分支。

原因：

- 本改动只涉及前端本地定时器和输入事件监听。
- 不新增接口调用。
- 不新增外部依赖。
- 不存在新的系统边界输入校验需求。

## 测试要点

### 正向场景

1. 进入留言页后，完全不输入，等待 2 分钟，应自动返回角色选择页。
2. 进入留言页后持续输入，每次输入都刷新计时，不应在输入过程中自动返回。
3. 输入若干字符后停止，连续 2 分钟无新的输入，应自动返回。
4. 粘贴一段文字后停止，连续 2 分钟无新的输入，应自动返回。
5. 删除文字也应算作有效输入行为，并刷新计时。

### 边界场景

1. 只点击输入框、不输入内容，2 分钟后仍应返回。
2. 只唤起键盘、不输入内容，2 分钟后仍应返回。
3. 输入后发送成功，页面应按现有 60 秒展示倒计时运行，不受本次逻辑干扰。
4. 切换角色后，应重新进入新角色的留言前状态，并重新开始该角色页面的空闲计时。

## 实施范围

预计只修改：

- `public/index.html` 中留言页空闲计时相关逻辑
- `public/index.html` 中输入框事件监听相关逻辑

不涉及：

- `server.js`
- 数据库结构
- Render 配置
- 审核 API

## 结论

本方案以最小改动实现更符合儿童使用场景的输入保护：

- 不放宽“先留言后解锁”的核心业务规则
- 不改变留言后 60 秒展示逻辑
- 只把“空闲”的定义从“在页面里待着”改成“真的停止输入”

这样既保住数据采集目标，也减少孩子在思考和输入过程中被意外打断的概率。
